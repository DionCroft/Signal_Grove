No interface will claim that unsupported server mutations, native audio endpoints, host-file retrieval, or push delivery are available. Live Hermes interoperability and physical/OEM behavior require their actual environments and remain explicit validation gaps.

The four confirmed defects are covered by desired-behavior regressions in normal test sources. Historical diagnostic probes remain outside those sources. Job refusal classification is limited to exact pre-mutation guards verified in the pinned stable/main cron handlers; arbitrary HTTP 400, network failure, malformed acknowledgements and later exceptions remain uncertain and never auto-repeat. Structured safe error codes and Retry-After are preserved; raw server error bodies are not shown.

Primary contracts: [API reference](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server), [pinned stable handlers](https://github.com/NousResearch/hermes-agent/blob/bf0203a794a07aac3ff764972ab9087baa4e4f4e/gateway/platforms/api_server.py).

Server discovery uses the pinned stable `api_server.py` handlers and `hermes_cli/inventory.py` payload. A normal catalog open uses the conservative server path; only **Refresh all provider models** sends `refresh=1`. Missing/false authentication metadata stays visible rather than claiming the provider is usable. Model browsing and per-turn selection are implemented; per-session locks, forks and steering are available through Session controls when advertised. Readiness uses the JSON status even on HTTP 200. Catalog expansion is lazy and provider IDs are deduplicated. The information dialog and whole-page scrolling keep bilingual/pinyin content reachable on small displays.

The request envelope freezes transport, route, full JSON and channel key before the Room submission transaction. Replay verifies the persisted hash and receipt binding; missing/corrupt files cannot be reconstructed or rebound. Only the original two-field/no-header form is rebuilt for pre-upgrade Runs receipts. Known runs can still poll/resume without needing their original inference body. Request bodies use bounded app-private files rather than large SQLite rows. A new turn retains its current request and removes older blobs for that conversation; chat deletion/cache clearing remove retained bodies. Storage remains app-private, not database/file encryption.

New mobile conversations receive a stable `X-Hermes-Session-Key` only when advertised; transcript/session rotation preserves that key. Existing/imported conversations retain their original header behavior to avoid silently moving their server memory scope. The key describes the logical conversation, never a fresh per-turn identifier or a credential. Live memory-provider behavior remains a server interoperability check.

The Chat Models and providers control applies requested model/provider, reasoning enabled/effort and service-tier fields to future turns on that connection. It does not claim the requested runtime actually won server precedence. Catalog account restrictions remain visible; manual IDs are explicitly validated by Hermes. Runtime choices use a targeted DataStore update so stale appearance/language saves cannot erase other connections' choices. The lost-admission fixture now changes selected model/provider after failure and verifies that recovery still sends the original full body, options, key and channel.

Chat uses compact tool/recovery/status actions with complete English/Chinese/pinyin accessibility labels. The status action opens the full outcome and run ID. Keyboard insets compact the header/navigation while typing. Empty Demo content scrolls; streaming follows the reply end only while the reader remains there, and a real drag/append regression checks that reading older content is respected. Final small-display screenshots verify actual reply text is visible, rather than only its card header.

Session mutations have durable scoped receipts: claim before sending, accept only the exact target/lineage acknowledgement, and never automatically repeat an uncertain result. Forking ends the original session as branched upstream; its client-selected child ID remains visible for reconciliation. A steering acknowledgement confirms guidance delivery only. Bounded session metadata excludes previews, system prompts and model configuration. Schema 6 preserves existing history, request hashes and channel identities. Legacy compatibility conversations remain on their original transport with local history; an upgraded capability response does not establish a native server session identity. Appearance, language, speech and notification edits patch only changed user fields and cannot restore an old connection snapshot.

Android 17 local-network enforcement is handled through manifest/runtime ACCESS_LOCAL_NETWORK support and an explicit Settings control. Private literal addresses and DNS answers are checked before connecting; revocation is checked again, and background checks never request permission. Public internet and device-local loopback remain available without broad LAN permission. See [Android documentation](https://developer.android.com/privacy-and-security/local-network-permission). The device matrix now includes API 37. Stable Espresso 3.7 replaces the transitive 3.5 test dependency after API 37 exposed its removed input-manager reflection path; this dependency is test-only.

Activity groups exact call IDs within a conversation, run, execution generation and category. Missing IDs are not guessed from tool names; a delegation ID needs a task index before it can identify a child. Public subagent identity, lineage, summary, counters and bounded file-name lists are shown without requesting private reasoning. Each conversation retains up to 500 recent tool/subagent events; the dialog reads the latest 200. A mismatched SSE run ID cannot retarget the receipt or save its activity. Explicit run.incomplete events are terminal outcomes.

Server usage and runtime are bounded, whitelisted metadata, attached to local responses and saved separately by durable submission. Refreshing history can replace local message IDs; the status dialog still opens up to 100 recent accounting records for that conversation. Conversation/cache deletion removes those reports. Requested and served runtime fields stay distinct; a partial new runtime report does not inherit an older provider. Cache counters, missing values and server-reported cost are not converted into an invented bill or summed across potentially cumulative session counters. Primary wire fields are verified in [pinned Runs handlers](https://github.com/NousResearch/hermes-agent/blob/bf0203a794a07aac3ff764972ab9087baa4e4f4e/gateway/platforms/api_server_runs.py).
