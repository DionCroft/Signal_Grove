# Signal Grove 1.1.0-beta.5 — model awareness and guided setup

**Preview, Android code 106.** Keep the same APK variant as your installed app.
The `-debug.apk` updates the development package; the APK without `-debug` updates
production. Both retain their original signing identities. Installing the other
variant creates a separate app; it does not migrate private conversations or
credentials. If you already have an owner development build numbered 106, install
the matching APK manually: equal versionCode does not trigger an update notice.

- See the verified model serving on Spark separately from the saved Hermes default,
  the conversation's next-request selection and last chat-reported telemetry.
  Home has a summary; Chat opens the complete Models & connection dialog.
  Foreground refresh is read-only, with explicit stale/cache/error states.
  The optional authenticated runtime observer must be installed on Hermes;
  ordinary model selection alone cannot prove which weights are loaded.
- Voice now separates Dictation from Read aloud and offers system speech/voice
  setup with explanatory unavailable states. On-device recognition and offline
  voices remain the defaults; no online speech processing is enabled implicitly.
- Manage stored projects with reviewed create/edit/folder/archive/restore/delete
  and active-pointer changes. Private drafts preserve omitted versus empty fields,
  and shared-home pending receipts fence conflicting writes. Active metadata does
  not adopt a chat workspace; metadata deletion does not erase files or stop work.
- Inspect host Kanban boards, columns, task details, comments, attempts, events,
  dependencies and attachment metadata. Board create/edit/archive/delete/current
  controls disclose initialization, repair, shared-storage and filesystem limits.
  Local phone Tasks remain separate from the host's boards.
- Edit task text, priority and assignment, comment with declared authors, delete,
  and create tasks with project/workspace, parent, skill, model and execution-limit
  choices. Exact approvals and durable one-send receipts distinguish ACK from
  matching stored configuration, exclusive creation and runtime effects.
- Add/remove task dependencies after separately approved child/parent reads and
  a fresh exact-value write review. Hidden current parents remain removable;
  running-child additions are disabled. Readiness and inherited subscriptions are
  explicit, and an unknown result is never replayed automatically.
- Follow **Settings → Server → Set up Hermes** for six offline steps in English,
  Chinese and pinyin: host/model setup, API credentials, private HTTPS, phone
  connection, separate management login and troubleshooting. Reading the guide
  changes no connection settings or server state.


## Validation and release boundary

The final Android source passed the strict debug build/lint/instrumentation tasks
and **528 JVM tests**, with no failures, errors or skips. The immutable app/test
pair passed **75 focused native cases** across API 26, 36 and 37, including
large-text narrow-screen dialog bounds, navigation and stale-response guards.
Actual narrow-screen SDK touch navigation and the visible Chat model dialog were
checked separately; an earlier SDK semantic-navigation failure remains recorded.
All **144 source/policy tests** and **15 runtime observer tests** pass. Original
compatibility hashes/variants remain intact; newly reviewed auth/plugin/profile
changes are pinned in the [source review](../contracts/reviews/2026-11-06-auth-plugin-guards.md).

Exact-commit hosted Android/compatibility CI, original-key signed production
assembly/lint, signature/manifest review, retained-data upgrade and uploaded-asset
digest verification are mandatory publication gates. Their terminal results,
run links and exact APK digests are recorded on the GitHub release page after
completion; this source document does not pre-claim those results.

The owner's older physical-device voice checks are separate from this APK. This
release does not claim a new physical/OEM certification, complete live-provider
interoperability, or completion of the broader audit. Independent task
model/reasoning forms, worker/dispatch/event/file-byte/pinning/transfer controls,
advanced automation/rooms, further integration/configuration and notification
routing remain tracked in the [execution ledger](../AUDIT_EXECUTION_PLAN.md).
