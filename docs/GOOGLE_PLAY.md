# Google Play release plan

Reviewed 26 November 2026 against the public beta.16 and Google Play's published requirements.

## What you can do now

1. Register at [Google Play Console](https://play.google.com/console/signup). A personal account suits an individual publisher. Choose an organization account if a verified legal entity will own Signal Grove. Organization verification normally requires a D‑U‑N‑S number. The registration fee is US$25 once. Complete the identity checks and, for a new personal account, verify a physical Android phone with the Play Console app. [Account setup](https://support.google.com/googleplay/android-developer/answer/6112435) · [Account information](https://support.google.com/googleplay/android-developer/answer/13628312) · [Device verification](https://support.google.com/googleplay/android-developer/answer/14316361)
2. Choose a public support email and recruit testers. For a personal account created after 13 November 2023, at least 12 testers must stay opted in to a closed test for 14 consecutive days before you can apply for production access. Internal testing can catch setup issues before the closed test. [Testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465)
3. Decide on upgrade continuity before the first Play upload. To let existing GitHub users upgrade in place, keep package **org.hermesmobile.app**, enroll the existing production app-signing key in Play App Signing, and use a separate upload key for the bundle. Choose a version code higher than the installed GitHub version, currently 121. Check package availability and verify the Play-generated signing certificate before inviting testers. The account owner handles the encrypted key transfer through Play Console if choosing this route. [Package names and app bundles](https://support.google.com/googleplay/android-developer/answer/9859152) · [Play App Signing](https://developer.android.com/studio/publish/app-signing) · [Version codes](https://support.google.com/googleplay/android-developer/answer/9859350)

## What Signal Grove needs before submission

| Area | Work |
| --- | --- |
| Distribution | Build a Play Android App Bundle from the same source. Exclude the GitHub APK update UI, background checks, installer and install-provider wiring from the Play build. Verify the merged Play manifest lacks **REQUEST_INSTALL_PACKAGES** and test that it never checks the GitHub APK feed. Keep the GitHub updater in the GitHub build. [Device and Network Abuse policy](https://support.google.com/googleplay/android-developer/answer/16559646) |
| Native compatibility | The app targets API 37, above Play's current API 36 minimum for new phone apps. All 24 packaged 64-bit libraries in the signed beta.15 GitHub APK passed static 16 KB ELF alignment checks. Verify the Play-generated APKs and run native inference on a 16 KB page-size device or emulator before relying on the native runtime in the Play build. Test both a fresh install and a Play-delivered upgrade from the signed GitHub APK. [Target API requirements](https://support.google.com/googleplay/android-developer/answer/11926878) · [16 KB page sizes](https://developer.android.com/guide/practices/page-sizes) |
| AI chat | Treat Hermes chat and on-device chat as covered by the generative AI policy. Add an in-app way to flag an offensive reply and send a reviewed report to the developer. Assess how the Play build prevents restricted output on both paths, including user-supplied GGUF models and Hermes endpoints. Decide which configurations can be supported for the first Play release based on that assessment. [AI-generated content policy](https://support.google.com/googleplay/android-developer/answer/13985936) |
| Privacy and permissions | Publish a public privacy policy and link it in About and in the listing. Complete Data safety based on the Play build's actual behavior. Map on-device processing, chat and attachments sent to a configured Hermes server, optional Android speech services, town weather, model downloads and AI reports. Describe data handling and deletion accurately. Complete the applicable declarations, including the **dataSync** foreground service if background model downloads are included. [Prepare for review](https://support.google.com/googleplay/android-developer/answer/9859455) · [Data safety](https://support.google.com/googleplay/android-developer/answer/10787469) · [Foreground service policy](https://support.google.com/googleplay/android-developer/answer/18265346) |
| Reviewer access | Provide steps to open built-in Demo. For functionality behind a Hermes login, use an isolated review instance with synthetic data and appropriately scoped reviewer credentials supplied in Play Console. The owner's Pi, tailnet, workspaces and production credentials belong outside the review setup. [Reviewer access requirements](https://support.google.com/googleplay/android-developer/answer/15748846) |
| Store listing | Prepare the title and descriptions, public contact, 512 × 512 icon, 1024 × 500 feature graphic and at least two screenshots. Complete content rating, target audience and ads declarations. [Listing assets](https://support.google.com/googleplay/android-developer/answer/9866151) · [App content declarations](https://support.google.com/googleplay/android-developer/answer/9859455) |

Start with a Play-specific build and an internal test. Verify that the store version updates the existing GitHub install with its data intact, then open the closed test and gather feedback before requesting production access.
