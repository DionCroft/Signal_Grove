# Team Gateway account report source review

Reviewed 2026-11-04 against stable **b200f5bc60e31588ba2cb60e288029c4a54ba5fa**. The original **f0d94882e89ab8d4098b5bb2f166adfb9ee0a0ab** baseline and every previously selected original fingerprint/variant remain intact.

This chunk adds only `GET /api/messaging/relay` and a separately approved browser handoff for Portal-managed instances. The route has no profile parameter: it sends `action=status` through the gateway control socket for `get_process_hermes_home()`. The native client first reads the explicit selected-profile channel catalog and verifies its native identity and profile-home mapping. Positive `relay_fronted` metadata is required; the reviewed channel helper emits that metadata only for the process home. It repeats this proof after the account read and discards changed home/platform/mode reports. This is a deployment contract, with no server revision/CAS or protection against a malicious server, changing proxy mappings, external process-home races, or equivalent filesystem/backend aliases.

The report retains bounded platform/account identifiers, display names, handles and bot/Portal URLs in memory. It requires the report's platform set to equal the verified fronted set and refuses malformed/duplicate/oversized data as a whole. The app displays counts first, with private details hidden until explicitly revealed. Closing, canceling, authentication failure or changing connection/profile clears the report. It does not create a Room receipt, request a link code, unlink an account, send a message, or acquire the gateway connector secret. A snapshot does not certify ownership, current access or delivery.

For Portal authority only, the destination must be HTTPS with no user-info, query or fragment. A separate frozen destination review and fresh approval are required; confirmation repeats the full scope/account read and compares authority and URL before browser handoff. The browser receives only the reviewed URL, uses its own Portal login, and receives no application bearer header. Unknown authority has no handoff. Invalid URLs remain unavailable with an explanation.

The watch adds six source modules: relay router, local control socket, upgrade-token helper, relay URL conversion, connector diagnostics and Portal URL selection. Original control/auth/media/Portal bytes were fetched from the primary GitHub contents API and matched their Git blob SHA. Selected helpers and import/binding fingerprints are tracked. Four additional original helpers in the already-known constants/auth modules were recovered from exact original source whose complete SHA-256 matches the existing baseline; no existing hash was replaced. Current selected control/auth/media/Portal helpers match the original fingerprints.

The relay router and connector diagnostics are absent at original F0 (primary contents API 404, with adjacent original files readable). They are recorded with null original source hashes and explicit source-introduction evidence, like the previously reviewed relay link module. Historical snapshots missing currently required modules remain incomplete. There are 48 newly accepted complete AST variants, each pinned to B200 and an explicit reason: 23 gateway report/error/import/binding entries, 9 router entries and 16 diagnostic entries. The report dispatcher’s status binding, process-home call, timeouts, HTTPS/credential separation, manager fallback, Portal selection and bounded error extraction were inspected. Existing original hashes and all previous variants are preserved. No wildcard or moving-ref acceptance was added. Unused provisioning/upload retries are outside this new selection; actual runtime/plugin/transport behavior still needs deployment validation.

The account-link POST, code-state GET and account DELETE routes are triaged as subsequent approval/receipt work. Inactive codes must never be treated as successful linking because Hermes defines inactive as used **or** expired. Portal authority must not be bypassed by minting connector codes. This read-only chunk makes no mutation parity claim.
