# One-use native PM preparation and activation acceptance

14 November 2026. The supported full-install component passes in one fresh
private Pi home. No canonical-home provisioning or live cutover is accepted.

## Execution and source boundary

`scripts/native_pm_preparation.py` accepts an exact reviewed source/home/store/
owner context, complete source hash inventory, native home identity, permanent
API interpreter digest, protected configuration preimages and fixed extras:
`agentic-contextgraph`, `all`, `discord`. The existing journal must own the exact
approved pending `pm_old` or `pm_new` step and its fixed preceding history. A
dispatch claim is spent before any PM effect; the actor and replacements cannot
reclaim it. The actor reports observed effects and does not verify its own
coordinator journal step.

The manager observes the current process over its existing pinned user-bus
connection. Its exact operation-named unit must have one reviewed main command,
no auxiliary hooks, no restart/delegation/failure action, finite runtime and stop
grace inside the approval deadline, and the sole current PID in its native
cgroup before and after PM. The helper reads documented Unit/Service properties;
it does not create units or change their lifetime. Acceptance uses separately
owned units with a 600-second runtime, five-second stop grace and control-group
cleanup. Kernel cleanup is observed, never inferred from an SSH disconnect.
See the [systemd D-Bus property reference](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html).

Each source gets a fresh isolated, no-bytecode SDK child. A stdin handshake first
binds its native PID/start/boot, executable inode/UID and cgroup to the reviewed
interpreter. Parent imports cannot contaminate a second SDK generation. The
supported `pm.runtime.run_cli` receives only `install` and the three fixed extra
choices; supported `pm.venv_is_current` verifies the result. No repair, lock
refresh, incompatible-plugin eviction, launcher publication, automatic retry,
model or credential action is requested.

Source/configuration reads use bounded no-follow native reads and compare inode,
ownership, links, mode, size, times and hashes. The API executable has a separate
128 MiB cap; source files retain their 32 MiB bound. Output captures retain a
four-MiB prefix per stream; overflow stays unknown. Private reports/receipts and
facts are independently matched, along with committed environment containment,
activation project identity, four exact source mtimes, absence of a test-env
marker and loaded SDK source hashes. Source and protected configuration must
conserve. Fixed checkpoint/error-class diagnostics omit exception text.

## Preserved failures and corrected SDK contract

1. An initial boundary fixture used the Python-build directory as its store;
   the strict context refused it before dispatch. The fixture now selects the
   permanent tools root and retains every case directory.
2. The next attempt refused the actual 70,558,608-byte interpreter under the
   source-file cap, also before dispatch. Native identity/hash review justified
   a separate binary bound; source/configuration limits were not relaxed.
3. A first real `pm.sync_venv` invocation committed a private dependency
   generation and returned true from supported currency checking. The parent
   refused it because `.project-root` and all four activation stamps were absent.
   Read-only recovery authenticates its report, facts native identity/hash and
   terminal owned units. That journal remains unverified and is not replayed.

The reviewed `pm/cli.py::cmd_install` advances activation inputs after its full
install succeeds; a dependency-only sync does not. The corrected actor calls
that supported command through `pm.runtime.run_cli`, then verifies its stamps.
It does not write stamps to turn the failed attempt into a pass. A regression
models a successful dependency operation without stamps and proves the result
stays held with an `activation` checkpoint and no replacement dispatch.

names, both stopped successful owned units/empty cgroups, actual SDK reports,
facts/activation/native ABI, receipts/journal, all 23,628 source inputs and 41

live service incarnations are unchanged. It invokes no PM or sync action. Of
the current 150 platform cases, 147 have scoped Pi cohort evidence; the three
older cases retain their separate scope. Cohorts overlap and are not added into
a claimed fleet-wide pass count.
