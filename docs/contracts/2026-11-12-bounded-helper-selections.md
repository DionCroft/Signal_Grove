## Findings retained and correction

The initial answer-only correction reaches a clean native garden answer and
passes29 vocabulary checks. Its code113 build also passes1,006 JVM cases/96
reports, zero-error lint (51 debug/50 release warnings), original signing and all
four ABI/DEX/64-bit16-KiB checks. That does not accept its helper: all six native
diagnostic topics exhaust384 tokens in hidden reasoning with no answer.

Using the pinned runtime's supported reasoning-budget sampler improves this to
five of six valid selections; first setup still emits an extra JSON bracket.
Strict application validation rejects it. Both failed stages remain recorded;
no generated instruction or invalid suggestion is accepted.

The follow-up now derives start/end markers from the model's chat session and
uses the upstream UTF-8-aware budget sampler. Hidden reasoning is bounded to
one quarter of the existing total allowance, capped at64 tokens. Non-reasoning
templates keep their normal path. This leaves room for answer text without
increasing chat's total limit. The helper returns to its original96-token total;
all original48/96-token physical completion assertions are restored unchanged.

A narrow immutable LocalCheckChoices type passes only the current topic's
reviewed IDs through the helper/JNI path. Both sides bound and validate the
choice set. The runtime builds a JSON-schema enum of every ordered unique
one-to-three-ID selection: at most85 alternatives from five choices. It cannot
receive caller-written schemas, instructions or commands. Ordinary chat has no
helper constraint. Strict Kotlin selection/source/scope validation still runs
after generation, and no generated advice executes tools or changes settings.
The32-bit unavailable shim receives the matching signature.
