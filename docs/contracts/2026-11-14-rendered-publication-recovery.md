# Exact rendered catalog, parent creation and retained recovery

14 November 2026. The renderer now binds its ten exact file/link targets to
native preimages and one-level parent-creation intents. A retained owned-only
fixture completes six forward file/mode stages and two actual recovery stages.
All 62 related methods pass on the Pi with no skips. This remains component
acceptance: service, PM, backup and admission stages are explicitly synthetic;
actual protected ancestry, live paths, authentication and full cutover are open.
No live file, permission, service, grant, credential, model or APK changes.

## Closed definitions and read-only native capture

`scripts/rendered_publication_catalog.py` derives paths, wrapper bytes and link
targets from the existing closed `plan_pi_runtime` renderer. Callers cannot
substitute individual targets, commands or source payloads. Layout is limited
to the named account's dedicated Projects/fleet child. The exact policy and
SDK-launcher hashes, fixed devices and authority belong to an externally
reviewed definition; hashes do not issue approval.

| Roles | Bound renderer destination |
| --- | --- |
| Source gateway/serve overrides | scripts/systemd/generation, exact two config names |
| Source client/serve wrappers | scripts/bin/generation, exact two command names |
| Runtime client/serve wrappers | The SDK's permanent command directory |
| Operator policy | The fixed private control-policy filename |
| Gateway/serve references | The two exact 100-signal-grove.conf drop-ins |
| Stable client reference | The named account's .local/bin/hermes |

Native capture is read-only. It binds all seven current 0775 directory identities,
stores planned 0755 postimages and captures old target metadata. It verifies
the real launcher bytes/mode, refuses unreviewed writable parents, preserves
different new-generation source and refuses an occupied proposed drop-in name.
Existing source is accepted only when it already matches the reviewed payload
and mode. Original CLI data is retained in memory with its native hash; only
supported absolute links or regular 0755 scripts can proceed to this recovery
path. Unsupported original permissions/forms require a separate exact plan.

The existing canonical operator-policy parser validates the reviewed new policy
and any supported existing policy. It is reused, not replaced by a new schema.
Policy bytes/old CLI data are excluded from repr and public metadata. Canonical
schema validation does not authenticate a live user or prove the protected
reader's full real ancestry. The strict protected reader remains unchanged.

Owned fixtures use a separate fixed virtual layout and uniquely named private
root, with all paths/payload references rebased inside it. Their scope is
explicitly owned_fixture_only; production template definitions stay review-only.
No arbitrary fixture path can masquerade as a live layout.

## Parent preparation under the original stage claim

`DirectoryCreation` represents one declared absent child under an exact existing
safe parent. It cannot recursively create missing ancestors or adopt a directory
that arrives after capture. A unique private 0700 directory is created, opened
and bound before its final name is installed. Owner/group/device/mode and empty
contents are checked; kernel no-replace publication and directory fsync follow.
The actual new inode is written into the private effect receipt before any file
inside it can be published. File bindings resolve to that witnessed identity.

The original reviewed catalog binds the creation intent; the derived native
catalog binds the resulting inode. Both enter the durable receipt under the
same one-use authorized stage claim, without a second dispatch capability.
All existing/new file preimages are rechecked before the first file effect.
Shared parents are created once. Collisions, symlink arrivals, post-rename
failure or deadline expiry preserve names and hold; there is no adoption,
automatic deletion, reconnect or compensation. Recovery cannot create a missing
parent as an absence shortcut; that outcome requires read-only reconciliation.

This uses the documented [Linux mkdirat behavior](https://man7.org/linux/man-pages/man2/mkdir.2.html)
and [renameat2 no-replace semantics](https://man7.org/linux/man-pages/man2/rename.2.html).
Unexpected umask/group/native modes refuse rather than silently adjusting an
unproven directory. Existing OS I/O blocking/supervision limits remain as in
the earlier primitive checkpoint.

## Retained composed forward and recovery fixture

`scripts/native/rendered_publication_fixture.py` creates a fresh private virtual
control plane with a generated policy and inert fixture launcher. It never
executes that launcher, starts/stops/reloads a service or contacts a worker/model.
Every non-file prerequisite is explicitly tagged synthetic in the retained
result, including the otherwise named backup/PM/drain/service stages.

Actual effects are: seven nonrecursive named mode changes, six rendered source/
wrapper files, private policy, two exact drop-in links and stable CLI. Five
publication parents are created: two source-generation directories, policy and
two unit drop-in directories. These exclude the fixture's initial scaffold.
Each stage's effects and receipt hash are independently checked before its
journal verification; already observed nodes are checked before dependent work.

The forward operation is explicitly held as unknown. Newer fixture data is then
written and retained. A new recovery operation binds the exact prior history,
approval and observed snapshot; it retires the new policy/drop-ins and restores
the original regular CLI. Seven mode changes remain 0755 under the fixture's
explicit disposition. Five displaced/retired entries remain available. No
database/model restoration, task replay or data overwrite occurs. Remaining
non-file recovery stages are also explicit synthetic rows; a complete fixture
ledger is not a full operational recovery receipt.

Independent read-only recovery inspects actual names, inode/UID/GID/mode,
symlink targets, bounded file hashes and every receipt. It checks ten exact
renderer paths, all eight actual stages, five publication parents, five retained
entries, raw history binding, original CLI bytes/mode, newer-data bytes and the
canonical policy parser again. It verifies all named native methods and exact
eleven source copies, terminal controller/child identities, unit scratch cleanup
and retained flow files. SDK inputs (23,628), 41 SDK caches, package files/caches,
app/tool facts, live references and original seven real ancestor modes conserve.
