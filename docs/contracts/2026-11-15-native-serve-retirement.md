## Implementation and trust boundary

`NativeServeRetirement` requires an exact `ServeRetirementSpec`, the shared
`NativeOperationalPaths`, original `CutoverJournal`, native manager and supported
forward `serve_retirement` or recovery `rollback_serve_retirement` authorization.
It checks the exact fixed journal prefix, approval/plan/root bindings and deadline,
then claims dispatch once before HTTP effects. It rechecks native owner,
configuration, source inventories and ancestry around the exchange. A replacement
actor cannot adopt that claim or overwrite an existing exclusive receipt.

The caller supplies an already-connected `PinnedRetirementHttp` transport and
signed-in provider bearer. Real `LinuxSocketOwner` proof ties that exact loopback
socket, kernel TCP inode, server file descriptor, UID, PID, start ticks and boot
identity to the reviewed native service. A callback reporting a synthetic owner
cannot substitute for this check. No login/discovery, reconnect or secret lookup
occurs in this actor.

Identity, idle, prepare and commit use that single connection. Busy diagnostics
or prepare responses hold with a false stage check. A lost commit response,
invalid permit, changed owner/input or receipt collision remains unknown and
cannot be replayed. Receipts are exclusive and fsynced, with a closed event
schema that excludes bearer/permit values. The socket and secret are closed on
terminal paths. The actor performs no cancellation, service start/stop, automatic
recovery or journal-stage verification.

Recovery can confirm an already-absent service only from its exact loaded,
inactive/dead, zero-PID, empty-cgroup native snapshot. Forward retirement refuses
absence. A successful running-service result reports the reviewed SDK's
**source-bound cooperative protocol** semantics; it explicitly sets
`independent_admission_probe=false`. This is not independent proof that an
arbitrary HTTP server has fenced every admission path. The executor must still
validate the supported SDK and its full admission/work/recovery behavior.
