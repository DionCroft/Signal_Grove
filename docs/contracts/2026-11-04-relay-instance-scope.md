# Team Gateway instance-local ordering review

Reviewed 2026-11-04 against the unchanged official B200 relay contract. `_ask_gateway` uses `get_process_hermes_home()` for the relay control socket; creation, state, report and unlink routes declare no selected-profile argument. Client positive launch-home metadata remains mandatory, but profile aliases that resolve to that home cannot be assumed to identify independent relay instances.

Previously the shared management claim was keyed only by canonical dashboard URL and selected profile. After an uncertain code/unlink request under one profile, another profile at the same URL could obtain a second claim. The local guard now includes all unknown/sending RelayLinkStart and RelayUnlink records at that exact URL in repository preflight and the atomic Room transaction. The private save/preflight-to-claim race is guarded too. Any pending relay record blocks new management claims at that address; ordinary pending records still use their original profile scope. No server idempotency or cancellation route is invented.

History visibility queries include cross-profile pending relay records before the 100-row bound while excluding foreign settled history. Only an opaque receipt key, pending state, current dashboard address and generic instance-pending marker are projected across profiles. Original profile, resource/inference hashes, actor, action, target, payload summaries and time are hidden, even when inference credentials are shared. Projected rows survive same-dashboard collector/profile changes without recovering private metadata; endpoint changes discard them. Rendering repeats projection for stale raw rows.

A current verified profile may explicitly mark one unknown relay receipt reviewed locally at the same exact dashboard URL. The original profile/credential need not still exist. The UI freezes the current target, discloses the instance-wide local effect, requires a fresh unchecked grant and discards changed-target confirmation. Sending work cannot be reviewed away; other unknown receipts retain their barriers. Review changes only that row’s state, with no remote request, retry, original capability read or success/cancellation inference. Original encrypted code and account-target bindings remain unchanged.

The fix uses existing schema-10 URL/action/state columns. Receipt keys, resource scopes, private history, request/result summaries and timestamps are not rewritten. Known acknowledged issuance/redemption observations remain separate from uncertain sends. No network route/payload, dependency or original source-watch baseline/variant changed.

This proves only local ordering at the same canonical address. It cannot identify aliases across DNS/proxy/deployment URLs, impose a server lock/CAS, order another device/browser or freeze a process/authority after preflight. Positive live gateway/connector/provider, Android-to-Hermes, TLS and physical/OEM verification remain separate audit requirements. Actual local/native evidence is recorded in [VALIDATION.md](../VALIDATION.md).

Primary contract: [official B200 process-home relay router](https://github.com/NousResearch/hermes-agent/blob/b200f5bc60e31588ba2cb60e288029c4a54ba5fa/hermes_cli/web_routers/messaging_relay.py), [gateway relay control](https://github.com/NousResearch/hermes-agent/blob/b200f5bc60e31588ba2cb60e288029c4a54ba5fa/gateway/relay/link.py). The existing exact source fingerprints and guards remain in force.
