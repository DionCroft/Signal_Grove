## Transaction and authority

`scripts/native_backup_transaction.py` binds a `BackupTransactionSpec` and its
reviewed digest to the original journal owner, exact forward/recovery prefix,
approval and finite native manager/controller. It supports `backup_pre`,
`backup_post`, `recovery_backup` and `recovery_backup_post`. SDK/dependency/
executor inventories, source/store role, interpreter, age executable, private
identity, recipient, private home/output parent and pinned Release target are
explicit inputs. It shares the journal's ten-role operational witness. Additional
descriptor walks bind every nested program/key/dependency parent, including the
installed Python directory's literal `+` name. Only the seven already-reviewed
mode exceptions may be group-writable; no permissions are repaired here.

Before any backup effect, the original stage is exclusively claimed and a
durable receipt created. A new private operation/stage directory must have an
absent preimage. It is never adopted, overwritten or reused. Child execution is
bound to the actual PID/start identity, executable inode/hash, owner and exact
finite cgroup. Reports and logs use exclusive private files and finite bounds.
Unknown effects remain with their original receipts; replacement actors cannot
repeat the snapshot, encryption or upload. No global SDK process reaper runs.

`scripts/backup_sdk_snapshot.py` runs as a private `-I -B -S` child. It adds only
the reviewed SDK/dependency paths; environment inheritance cannot supply another
home, backend, key or remote endpoint. Normal SDK/dependency imports compile the
verified source bytes directly, avoiding unchecked bytecode caches. Native
extensions must match the reviewed code map. Full source inventories are checked
before/after, including actual native file metadata, owner and protected parents.
This binds the installed inputs; it is not a general upstream/transitive code
review or proof of every possible dynamic plugin import.

The child calls the unmodified SDK's supported `run_backup` once with `keep=0`.
Its selection uses the actual SDK iterator, checks ordinary file hashes/native
preimages before/after and treats `.db` files as SQLite snapshots. It requires
the exact root and reports the explicit selection and loaded-source bindings.
The parent independently verifies the archive's members, CRC, bounds and SQLite
integrity. Empty or incomplete backups cannot become a fresh-backup result.

The parent encrypts once with the pinned age binary/public recipient, decrypts
once using the exact private identity FD and compares the complete archive hash
and content proof. Its [age CLI usage](https://github.com/FiloSottile/age#usage)
uses explicit input/output streams. Only after this proof does it create the
checksum and invoke the [private publication component](2026-11-14-private-backup-publication.md).
Both downloaded assets must match the verified ciphertext/checksum. Program,
key and source inputs are rechecked before/after publication. Verified plaintext
is removed only by its exact recorded identity, with fsynced intents/receipts;
failed or uncertain artifacts remain. It never restores or prunes source data.

Only the complete result exposes the stage-specific `fresh_backup_verified`,
`post_backup_verified` or `recovery_backup_verified` check. The actor does not
advance the journal's stage itself. Caller admission/work/model/credential gates
and the full coordinator transaction still need independent real observations.
SQLite consistency is per supported SDK snapshot; no whole-fleet atomic freeze
is inferred from this component.

## Explicit completeness holds

The current implementation requires file-backed configuration and built-in
memory. It strictly parses root and named-profile configuration, checks merged
SDK memory selection and refuses active/malformed/unknown external providers,
declared external paths or linked profile homes. It cannot accept a provider
failure as an empty list. The inspected SDK's convenience collector intentionally
swallows provider errors; that behavior alone cannot establish backup completeness.
Configured external providers need reviewed path/selection support before their
integration/backup acceptance can close. No inference is made that the live Pi
already meets the fixture's built-in-memory precondition.

The private publisher retains its under-2-GiB-per-asset limit. Size, selection,
report or native-unit deadlines hold instead of splitting, silently omitting or
retrying data. Source content is not assumed unchanged merely because a lock or
socket exists; unknown stage outcomes require exact artifact/receipt review.

## Actual PM code semantics and preserved failures

The first preflight refused installed dependency files because it incorrectly
required one link for all code. Read-only recovery proves no acceptance home or
unit had started and observes 5,033 code files/148,062,662 bytes. Their actual
modes are 0600/0711, with link counts 2/4/5. The private wrapper initially retained
the same assertion after the source correction; that second preflight failure
also starts no unit and stays recorded. [uv documents linking installed packages
from its cache](https://docs.astral.sh/uv/reference/settings/#link-mode).

Reviewed code now has a separate typed policy: owner-readable regular files,
no group/other write or special privilege bits, exact inode/link-count/time/hash
witnesses and a hash check before ordinary source execution. Alias changes refuse
before execution. Code is not relabelled as read-only or detached from PM caches.
Keys, programs, archive and output files retain their distinct single-link rules;
a reviewed-code object cannot substitute for an exclusive input.

The first Windows discovery run mixed exact class generations; its six errors
are retained, and the harness now binds both new modules to one generation.
The first native cohort exposes an unnormalised `O_NOFOLLOW` error; the reader
now preserves missing-file semantics and returns a bounded refusal for other
native open failures. The next cohort reaches the synthetic SDK producer, which
incorrectly tried to read its inert runtime directory as a flat data file.
Its partial fixture ZIP and receipt remain, with zero encryption/upload effects.
The corrected flat test producer excludes that scaffold; the separate actual
SDK trial verifies real recursive selection. No failed backup is replayed.
