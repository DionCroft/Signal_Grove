# Descriptor-anchored publication ancestry

14 November 2026. Publication now has a native descriptor path witness integrated
with file/mode effects and the retained owned recovery fixture. The actual Pi
preflight also captures successfully and refuses publication with its unchanged
permissions. This closes the missing publication-ancestry component; it is not
the complete cutover backend or permission to activate it.

## Closed capture and identity checks

`CapturedCatalog.capture_ancestry` derives endpoints from the existing renderer's
ten targets, SDK command parent and selected source root. The exact original
capture hash is required. Callers cannot replace individual paths through this
factory. Seven mode roles and one-level creation intents come from that same
captured catalog. Root/source contents still require the separate immutable
inventory and runtime-readiness gates.

Production descriptor walks begin at `/`, open one directory component at a time
with no-follow/directory/close-on-exec flags and bind device, inode, UID, GID and
mode. Root-owned safe ancestors are supported. Foreign ownership, unsupported
modes, unlisted group/other writability, symlinks, missing required source roots,
replacement inodes and arrivals at declared absent parents refuse. Only the
exact seven captured 0775 directories are allowed in the preflight witness.

Owned acceptance uses an explicit private fixture root and a separate scope.
Directories above that root are not protected-ancestry acceptance. Its selected
source directory is an inert scaffold, not an actual SDK-source readiness proof.
The real-layout read-only capture separately walks from the real filesystem root.

## Integration with actual publication effects

`NativeFilePublication` accepts the native witness and its externally reviewed
hash. The guarded stage checks ancestry before claiming dispatch and throughout
authorization checkpoints, and obtains existing parent descriptors through the
bound walk. Publication requires all seven mode effects already observed; the
guard never treats proposed mode bits as actual state.

After each successful descriptor chmod, the original journal-bound actor records
the native postimage and advances that exact role. After an explicit new-parent
publication, its native inode is recorded in the receipt before the witness
accepts that parent. Unexpected existing directories are not adopted. Each
guarded receipt binds the original ancestry hash and starting state hash; the
returned result binds the observed state. Catalog identity stays fixed while
observed state advances. There is no serialization/resume shortcut that guesses
the state after a crash.

The retained owned fixture now requires this guard in all eight actual forward/
recovery file/mode stages. Its plan binds the ancestry hash. Independent review
recomputes every state transition from raw mode/parent observations and verifies
the final native directories, files, links, preserved newer data and restored
CLI. Five retired entries remain. Non-file prerequisites remain explicitly
synthetic, and modes stay 0755 under that fixture's reviewed recovery disposition.

Legacy standalone primitive tests can omit the witness and retain their existing
component-only scope. That omission does not establish protected ancestry for
the future live backend. The complete backend must require the reviewed guard
and separately bind journal, PM, backup and other operational paths. No new CLI,
default live adapter, approval issuer or automatic recovery is introduced.

Native I/O still has the existing supervision/deadline limits: this guard checks
identity and observed effects; it cannot promise atomicity of the entire tree or
preempt a kernel filesystem operation. A claimed-stage drift is held as unknown,
with files/receipt/journal preserved and no action replay or compensation.
