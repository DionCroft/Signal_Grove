# Team Gateway unlink source review

Reviewed 2026-11-04 against stable **b200f5bc60e31588ba2cb60e288029c4a54ba5fa** and the matching current main relay file blobs. The original F0 baseline, every original fingerprint/field/source hash and all earlier reviewed variants remain intact. This adds two exact B200 AST variants and one used management route; no new source module or moving-ref acceptance is needed. Current coverage is **1,735 selected fingerprints / 237 fields / 63 management routes / 133 modules**.

The official DELETE route is `/api/messaging/relay/{platform}/accounts/{platform_user_id}`, with no declared profile or body. Its router function forwards those exact two fields and `action=unlink` through the already reviewed process-home control socket. The gateway helper POSTs `/manage/unlink` with `platform` and camel-case `platformUserId`, then returns only `unlinked:true`. The HTTP wrapper removes the internal `ok`; there is no account echo or remote revision/idempotency key. The helper does not itself recheck Portal management authority. A lost/failed reply can follow a mutation, so the mobile client does not classify arbitrary HTTP errors or a timeout as safe to repeat.

Before one DELETE, the phone requires explicit connector authority, an exact selected account ID/name/handle and bot link, the verified original owner/profile-home/fronted platform/mode proof, and a new private reveal plus unchecked approval. It repeats the full account/scope read before storing the exact target encrypted and atomically claiming the shared management resource. A concurrent claim refuses before send and cleans only the unclaimed private target where storage permits. Selected IDs preserve literal Unicode/dots/colons/@ but reject path separators, query/fragment characters, controls and ambiguous dot segments. The route keeps the configured prefix, bearer isolation, strict TLS and no redirects/retries.

Only typed boolean `unlinked:true` captures an acknowledged receipt, before the separate account readback. The account still being listed or a changed later manager/bot context produces a distinct observation. Failed/canceled/changed-home readback preserves the ACK. Nothing proves provider credential revocation, deletion of a platform account, stopped delivery or the disposition of in-flight messages. Report metadata can be stale, bot identity can change without a changed reported URL, and authority/process home can change after preflight; the host exposes no revision/CAS for stronger binding. Backend/proxy/filesystem aliases and other devices remain outside the local exact-resource pending guard.

Room receipts contain platform, one-account count, original profile-home fingerprint and typed ACK flags, with no account ID, name, handle, bot URL or hash of those values. Exact original targets are held in a separate AES-GCM Android-keystore-encrypted local cache bound to receipt key, API credential scope, exact normalized dashboard URL, profile, actor, action, platform and original home fingerprint. Original targets cannot be replaced under an existing binding. The cache retains acknowledged/uncertain history for local receipt inspection, with explicit disclosure before approval, no automatic replay and no silent eviction. Bounds are 32 targets per exact signed-in profile and 128 total; a full/unavailable cache refuses before claim/send.

Local historical inspection has no network request and never treats the saved target as current. Clearing requires a separate exact-owner review and fresh grant; it removes local targets only, leaving receipts/pending guards/remote accounts untouched. Signing out or forgetting the inference credential removes that scope’s private targets. If the new cache is unreadable during credential removal, it is discarded rather than preventing sign-out; no remote operation is inferred or repeated. A subsequent login must independently verify the original actor/profile before private target access. Portal and unknown authority remain read-only for unlinking; Portal handoff stays separate. Link-code creation/state remain subsequent work.

The new negative regression mutates route identity, action, exact account forwarding, added profile input, connector endpoint/body field, strict ACK and dispatcher target. Original absence of the router/link modules at F0 remains documented by the earlier primary-source 404 evidence; these newly selected functions receive pinned complete AST variants rather than fabricated original hashes. Actual official-server HTTP proof covers authorization and the stopped-gateway route; positive connector unlink, Android-to-live-host, vendor, TLS and physical/OEM behavior remain separate validation.
