## Original-actor preparation and descriptor checks

`prepare_inputs` performs the complete content/native identity read under the
original journal, exact approval, finite controller, current native role and
shared operational path boundary. Preparation claims no dispatch and makes no
HTTP/service request. Its process-local typed witness belongs to that actor and
execution; it cannot be supplied as external JSON or adopted by a replacement.
Only one preparation and caller-authenticated transport binding are accepted.

`VerifiedInventory` reopens every bound parent directory through native directory
descriptors with `O_NOFOLLOW`. It checks all native file and directory identities,
including inode, owner, mode, size, mtime and Linux ctime. A depth-first traversal
keeps only ancestor descriptors, with an explicit 64-component bound. Witness
integrity, current process and the exact inventory/path objects are checked.
Complete-map digests and counts keep receipts bounded. These are point-in-time
observations, not an atomic filesystem freeze.

Transport binding checks the original preparation/authorization and current
native service/socket owner. The fresh full identity walk runs immediately before
the original journal's one-use dispatch claim and after the committed response.
It is not duplicated at binding. Source/executor drift, directory redirection,
changed approval/deadline/owner, preparation adoption and socket replacement
refuse before HTTP effects. Unknown effects retain their original receipt; there
is no reconnect, cancel, automatic retry, service action or journal verification
inside the actor. The result retains the SDK's source-bound cooperative protocol
assumption and `independent_admission_probe=false`.
