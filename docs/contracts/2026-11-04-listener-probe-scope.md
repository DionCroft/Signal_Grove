# Listener-scoped endpoint-probe ordering review

Reviewed 2026-11-04 against unchanged official B200 `validate_custom_endpoint` in `hermes_cli/web_routers/config_env.py`. It declares only `body: CustomEndpointUpdate`, reads explicit address/key/API-mode/model values, and uses listener-side model/transport probe helpers. It neither reads a selected profile nor scopes execution through a profile resolver. The client already discloses listener networking and sends no profile query/body field.

The former local receipt resource used dashboard URL plus selected profile. After a lost probe response under one profile, another profile at the same dashboard could acquire another claim despite using the same listener context. CustomEndpointProbe now shares the existing exact-dashboard unknown/sending domain with RelayLinkStart and RelayUnlink. Existing records participate immediately through URL/action/state queries without rewriting keys, resource scopes, request/result summaries, owners or timestamps.

Preflight refuses before any network or fresh-key exposure. The final Room claim also refuses when another profile claims work during the last scope read, before the probe POST. Original input profile/home/identity checks remain in place; request values, credential selection, no-redirect/no-retry transport, strict typed acknowledgement and optional-result handling are unchanged. Known negative/unreachable reports are acknowledged outcomes, not uncertain sends.

Generic shared-work cards expose only the opaque key, current dashboard address and pending state. Original profile/hash, actor/action/target, summaries and timestamps stay hidden across profiles, even with shared inference credentials. A fresh local review can mark one exact unknown record reviewed from a current verified profile, including when its original profile/credential is absent. Sending work cannot be cleared. Review does not contact the server, read original private capabilities, confirm an outcome, stop remote work or repeat a request. Other pending records retain their barriers. A shorter grant label accompanies the full scoped effect disclosure in English/Chinese/pinyin.

The domain is the exact canonical dashboard address, including deployment prefix. It is a device-local ordering policy rather than a server identity/lock/CAS. URL/DNS/proxy aliases, external clients and process changes after preflight remain outside that guarantee. Profile-scoped MCP probes retain their separate domain. Unprofiled OAuth flow-ID operations retain their existing exact original receipt/API/profile/actor binding; the absence of a profile query does not erase that private capability identity.

No route/payload, source-watch baseline/variant, database schema/version, dependency, private code/account cache or release version changed. Native regressions cover blocked fresh keys, post-preflight races, cross-profile privacy/review and sending-state protection. Actual results are recorded in [VALIDATION.md](../VALIDATION.md); these fixtures do not certify positive live provider, Android-to-Hermes, TLS or physical/OEM behavior.
