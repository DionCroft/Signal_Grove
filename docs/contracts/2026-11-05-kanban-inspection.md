# Signal Grove host Kanban inspection — 5 November 2026

Development beta.5 (code 106) adds native remote-board inspection through the separately authenticated dashboard plugin. It does not merge host cards into local phone tasks or complete the broader Kanban/automation audit.

| Explicit read | Official response |
| --- | --- |
| `GET /api/plugins/kanban/boards` | Board metadata/counts and separately reported host current slug; `include_archived=true` and explicit profile |
| `GET /api/plugins/kanban/board` | Complete status-column observation, tenants/assignees, event cursor and host time; explicit board/profile, archived cards included |
| `GET /api/plugins/kanban/tasks/{id}` | Exact task, comments, attempts, events, attachment metadata, dependency IDs/titles and child handoffs; explicit board/profile |

No upstream code was imported or executed.

The host shares its Kanban root across profiles, with environment overrides; reported profile home is an access-routing fence. Explicit board selection never moves the host current pointer. Board catalog checks around a read compare slug, archive and reported database path, without claiming filesystem equivalence, a CAS/revision or a cross-request atomic snapshot. GETs can load plugin code and initialize/migrate/repair host storage. Frozen reviews disclose those effects before requesting private data.

Whitelisted immutable projections keep exact statuses and independent attempt/outcome/timestamp facts. A future status survives fallback column grouping. Full detail requires exact task ID and matching ownership of comments/runs/events/attachments. Duplicates, malformed present fields, overflow and bounds fail closed. Limits are 2,000,000 response bytes, 500 boards, 64 columns/2,000 tasks total, 2,000 comments, 1,000 runs, 5,000 events and 500 attachment metadata rows; text fields have explicit per-field limits. Host paths remain literal selectable text. Claim locks, idempotency keys, arbitrary run metadata/event payloads and stored attachment paths are omitted. Missing links remain IDs, and failed linked reads remain errors.

Each read is separate and cancellable, uses the frozen management identity/profile and encoded selectors, and checks access mapping before/after. Stale owner/home/generation/board/task selection cannot submit or publish. Verified access/mapping changes clear private views. Local filtering is network-free. Closing/cancelling clears private state; there is no read replay, automatic dispatch, model call, new durable operation or Android schema change.
