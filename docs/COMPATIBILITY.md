# Compatibility and protocol scope

Android 8.0/API 26 minimum; compile/target API 37. Foreground local-only speech needs Android 12/API 31 plus an installed service/model. System recognizer and TTS availability vary by device. Network speech is explicit; physical audio quality is not inferred from text/policy tests.

The app follows the [official Hermes API server reference](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server/) and the upstream gateway/pending-control contracts reviewed during these milestones. No minimum Hermes version string can establish all feature support across changing/forked installs: authenticated capability discovery chooses native sessions/Runs, session streaming or OpenAI-compatible fallback. Unsupported routes remain explicit. Exact unknown-run acknowledgement is exposed only when advertised. Jobs use documented bearer-protected routes after per-connection opt-in; no invented `jobs_admin` capability is assumed.

API-owned sessions are supported; imported CLI/Desktop shared ownership is outside scope. Compatibility completion responses do not prove tool/run completion. Native Runs support persisted request keys and sequence-based manual resume; expired receipts/event buffers require server review. Jobs preserve unedited fields. MCP OAuth and dashboard native sign-in use the separate reviewed management bridge. Generic file input, a remote agent backend, automatic approvals and a server-push service are not included. Structured image history and native image picking are available on the development branch; the reviewed share target is implemented.

The shipped Demo is a local simulator. Fixture tests validate request/response and lifecycle behavior without a production agent. The owner's live endpoint/credentials and physical microphone/speaker hardware were not supplied. See the release validation record for device matrix, exact counts and any remaining manual checks.

Development `1.1.0-dev` adds read-only `GET /health/detailed`, `/api/model/options`, `/v1/skills` and `/v1/toolsets`, exposed when their endpoint entries are advertised. Each configured prefix and bearer credential is retained. A successful HTTP diagnostic response may report degraded readiness. The catalog includes unavailable/unauthenticated providers and optional capability/pricing hints; those are server metadata, not a guarantee of runtime availability or cost. Integration execution still happens on Hermes using its configured API-server toolsets.

Schema 5 preserves earlier sessions/receipts while adding a request hash and optional stable channel key. Full requests are bounded to 10 MB outside Room rows; text messages are capped at 64000 UTF-16 code units. The exact header/body is reused on a missing-ID Runs recovery within the existing 23-hour client window. The server's retention/admission guarantees still govern replay. Structured image history, native image picking and request-envelope support are implemented; the reviewed share target is implemented. Requested model overrides are implemented.

Requested `model`, `provider` and `model_options` are now supported on Runs, session chat and compatibility requests when model-option support is advertised. The client emits only the documented reasoning enabled/effort and service-tier option fields. No model/provider SDK or provider credentials are installed on the phone. Choices are requests; session locks, routes and server/provider validation still apply. Advertised per-session locks, forks and active-run steering use exact acknowledgements and durable no-replay operation receipts. Schema 6 adds bounded cached metadata and these receipts. There is no verified clear-lock route. Forking marks the original session branched on Hermes. Steering acceptance is not execution completion. Legacy compatibility chats keep local history and cannot target native session controls without verified native identity.

Android 17/API 37 requires explicit local-network permission for LAN/private-address connections. Settings can request it or open system app permissions; denial does not block public internet endpoints. Permission-aware DNS also detects public-looking names resolving to private addresses. Loopback traffic remains device-local. The operating system enforces permission changes on sockets; a socket blocked after revocation may still surface as a generic network timeout. No permission dialog is launched from startup, a worker, or an uncertain operation replay.

Schema 7 adds tool call/generation/sequence identity, bounded public subagent metadata, response accounting and separate run accounting records. Earlier activity migrates without invented call IDs or usage. Streaming and GET accounting share the durable submission guards. Accounting imports do not guess associations between server message IDs and local response IDs; their run/turn records remain available separately after transcript replacement. Runtime provider/model fields come from runtime metadata, not the top-level requested-model echo. Server token counters can be cumulative; absent counters are never rendered as zero, and no provider cost is calculated from a catalog price. Public child usage/cost fields are displayed when supplied. Live provider fallback and accounting remain unverified.

Schema 8 preserves existing messages/accounting and adds bounded image references. Inline images are normalized into private files rather than SQLite rows; plain JSON strings are never guessed to be media. Server history can contain up to eight image parts per message within the mobile response/memory limits. Native Runs uses an array of user messages whose content contains image parts; session chat uses parts directly, and compatibility history uses per-message content. Frozen requests retain the full exact encoded body independently of display-cache files. A missing/unsupported image in compatibility history cannot be silently removed from the next request. Large pages can retry smaller read-only GETs; mutations retain their no-replay policy. Generic uploaded files, host-file retrieval and arbitrary artifact routes remain unsupported.

Native picking uses existing AndroidX Activity APIs without broad storage/camera permissions or a new provider SDK. Up to three content-URI images can be staged; document fallbacks may allow selecting more, so the app checks the count again. Staging is local, cancellable, scoped and ephemeral. A complete encoded request remains separately frozen for recovery; explicit retry can restore its original JPEG pixels rather than recompressing them. Decoder/source limits and the 10 MB frozen-request limit still apply, especially to compatibility transcript replay. Picker contract dispatch is tested with an intercepted Android result and a test-APK-only provider containing generated pixels. This does not establish physical gallery/cloud-provider/camera behavior or live vision-model support.

The Android share target advertises image MIME types only. It receives transient content-URI access, bounds/validates the selection and caption, and requires an in-app target review before staging. It does not infer a server/session from untrusted intent extras or submit a run automatically. The activity uses a single task instance for warm shares; pending/consumed share state is explicitly restored. Tests launch real Android share intents against the existing activity with generated fixture URIs, including recreation before and after review. Sender-specific URI grants, real galleries and process-death/provider behavior still need physical/live checks.

Named connection profiles are local mobile identities bound to exact API URL/token pairs, distinct from Hermes server profile selection. Credential rotation creates a new scope. Old cached history is available read only after credential removal; uncertain work remains attached to the original credential. The separate native management bridge verifies dashboard identity and requires explicit authenticated server-profile selection. See [management contracts](MANAGEMENT.md).

## Stable v0.22.6 source recheck

During this implementation, stable moved to [v0.22.6](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.6), commit `f0d94882e89ab8d4098b5bb2f166adfb9ee0a0ab`. Static API comparison found no removed used routes, changed used flags, changed cron limits or removed used job-update fields. The removed browser-extension/artifact routes were already outside the mobile protocol. MCP toggle/delete/test route bodies and acknowledgements are unchanged; the MCP callback helper now resolves public URLs from the listener state. Native authentication now limits provider selection to interactive providers and records native-issued sessions before allowing their refresh. Mobile already exchanges native codes and never imports browser/provisioned sessions. Source inspection found no required change to those implemented wire contracts; this is not live interoperability certification. The new dashboard cron create fields `timezone`, `grace_minutes` and `catch_up` belong to the upcoming typed automation contract work. Historical audit evidence remains pinned and unchanged.


Reviewed host agent-plugin installation uses the scoped gateway contract and the inspected commit guard, without force or ref override. Optional activation details remain separate from mandatory installation acknowledgement; unknown replies are never replayed automatically. Desktop UI components are not hosted on Android. Reviewed enable/disable is implemented with canonical keys and separate configuration readback. Reviewed directory removal is implemented with exact profile-root proof and separate reported-absence checks. Reviewed updates now support separate capability/caution decisions with explicit unbound-proposal limits, durable acknowledgements and catalog metadata readback. Git revisions remain unverified; separately reviewed non-secret settings now use one-key typed writes with private transient values and distinct ACK/readback. Environment credential save/removal now uses separate reviewed profile-bound dashboard routes, with metadata-only reads, blank replacement input, no secret reveal/probe and durable acknowledgements distinct from exact-value verification. The pinned listing cannot reliably verify dotted settings. See [management limits](MANAGEMENT.md#reviewed-agent-plugin-installation).


Host model inventory uses separately authenticated management `GET /api/model/auxiliary` and `GET /api/model/options`, with explicit selected profile and pre/post profile-home checks. Its explicit catalog refresh can cause host provider probes/cache work and discovery persistence. Configured assignments, plugin effective inheritance, optional authentication reports and model IDs remain metadata; keys, endpoint URLs, raw warnings and unconsumed pricing/usage are omitted. Reviewed main assignment now uses scoped `POST /api/model/set` with explicit consent, durable single-send receipts, typed pre-assignment warning refusal/override and normalized acknowledgements. Reviewed auxiliary assignment, reasoning and reset controls are described below. MoA preset writes are described below. Phone requested runtime choices and session locks remain separate. See [management behavior and pinned contracts](MANAGEMENT.md#host-models-and-providers).

Management → Host models and providers now supports auxiliary writes through the same verified `POST /api/model/set?profile=<explicit-name>` contract. Both query and body name the reviewed profile; scope is `auxiliary`. Per-slot edits can keep the exact reported route while changing reasoning, select an eligible reported catalog model, or explicitly choose `auto` with an empty model. Bulk assignment sends an empty task; the dedicated global-reset action sends `__reset__`. No endpoint, API key, guessed revision or idempotency field is submitted. Slots not exposed by this dashboard assignment API (even if present elsewhere in Hermes defaults) are unaffected.

Reasoning **Keep** omits `reasoning_effort`; **Inherit** sends JSON null; **Disable** sends `none`; the seven canonical effort levels are explicit strings. Null is not the same as reset: Hermes writes an empty override for a slot with a shipped reasoning default (notably voice), whereas global reset removes overrides and restores shipped defaults/plugin inheritance. GET collapses some falsy/empty values, so an unreported reasoning field cannot prove raw-file removal or inheritance. Runtime/provider support is separate. Choosing auto alone does not fully reset a slot: same-provider and bare-custom assignments can retain endpoint/credential/API-mode overrides. The native read projection hides endpoint addresses and credentials; their undetected rotation can race a review.

Global reset removes each current dashboard slot's model pin, reasoning override, endpoint and endpoint credential/API-mode references while retaining other task settings. Built-in defaults and plugin inheritance can apply again. Both bulk operations target the host's slots at execution time, including plugin slots registered after the review/preflight; no server revision guard exists. Native reviews disclose this dynamic scope and list only the observed snapshot. A bulk assignment ACK can report a different affected-slot list, which is retained separately; reset ACK contains no exact affected list and the app never invents one. Fresh preflight refuses a changed visible inventory before claiming/sending, but cannot eliminate later races or managed-policy overrides.

Cost/data-training warning responses are exact typed known refusals, recorded without raw warning text. A separately reviewed, unchecked-by-default approval sends one new operation with `confirm_expensive_model=true`; no override is automatic or bound to an upstream warning revision. Shared Room management claims block other mutations while outcome is sending/unknown. Lost replies, cancellation, arbitrary HTTP errors, redirects and malformed/wrong-task acknowledgements stay uncertain and are never replayed. A captured ACK survives later readback failure/cancellation. Current metadata is a separate observation, not proof of exact persistence, credential removal, causality, plugin behavior or adoption by an already-running call. Receipt observation opens a fresh model read review and performs no automatic network call or mutation. Schema 9 and the existing app version are unchanged.

Management → Host models and providers → **Mixture-of-Agents presets** supports explicit-profile `GET /api/model/moa` and `PUT /api/model/moa`. Opening the inspector is local; a separate read review includes normalized named presets/selectors/privacy plus the main/auxiliary/provider catalog read and its disclosed probes/cache/discovery effects. Required named fields, complete finite numeric values, boolean reference/preset states, no recursive `moa` slots, selector membership and consistent optional legacy flattened aliases are checked. There is no fallback to an invented empty/default map. Bounds are 128 presets, 64 references per preset, 4096 total references, bounded IDs and a 2 MB encoded write. Values outside those bounds are unsupported rather than silently truncated.

Edits remain local until a frozen complete-map review and new checkbox confirmation. Native controls support copying reported presets under a new nonduplicate name, removal while retaining at least one preset, default/configured-active selection or clearing, ordered reference add/copy/remove/movement/enable, preset enable, reference/aggregator catalog routes and canonical reasoning, nullable provider temperatures, nullable positive reference timeout, `user_turn`/`per_iteration`/canonical `every_n:N` cadence and `loud`/`silent` failed-reference disclosure. Temperatures may be any finite value; the timeout has no artificial five-minute cap. Null timeout inherits the host's uninspected auxiliary MoA-reference timeout. Existing routes may be retained without claiming usable credentials; novel routes require an authenticated/unrestricted catalog report. The MoA virtual provider cannot be nested inside a preset. These are configuration choices, separate from phone requests and running-session adoption.

The PUT is an authoritative full named map: omitted names are deletions, not a partial patch. Both query and body identify the explicit profile. No guessed revision/idempotency/approval flags, legacy flat payload, endpoint, API key or privacy-policy write is sent. The source merges surviving preset/aggregator dictionaries and preserves the stored root privacy-filter policy, but replaces reference arrays: hidden reference-slot extensions can be discarded. A new duplicate contains only the reported supported fields. These are source semantics, not an exact-file-preservation attestation. GET normalizes/repairs invalid stored configuration, and saving can persist the displayed normalized defaults. Another writer can race preflight. MoA PUT performs no model-selection warning guard or credential/inference validation; reference count, cadence, timeouts and reasoning can affect provider calls, spend and sharing. Full-map reviews disclose these effects and the provider/catalog read phases.

Two verified endpoint limitations are explicit. The response can report bespoke reasoning from a stored dictionary even though `MoaModelSlot.reasoning_effort` only accepts strings; a full round-trip would drop that value, so such a map remains inspectable with editing disabled. Also, `_merge_partial_save` deep-merges surviving aggregator dictionaries. The normalizer omits null reasoning, so it cannot clear a previously stored aggregator effort through this PUT. That specific default/clear choice is disabled, and the typed request refuses it. Reference slots are replaced as a list and can clear their reasoning; canonical aggregator levels can still be assigned. Privacy mode is shown read-only because this payload does not declare it. These limitations must be revisited if the watched server contracts change.

Fresh owner/home/main and full normalized-map checks plus selected catalog metadata precede one shared management claim and one PUT. Typed successful normalized configuration is durably acknowledged before readback even when it differs from the requested map; the inspector/receipt call out the different report. A later failed/mismatching/cancelled read cannot erase ACK. HTTP failures (including 422), malformed/contradictory replies, lost connections and cancellation after claim remain uncertain, survive recovery/chat clearing, and block MoA and other mutations across actor rotation. No automatic new-key replay occurs. Receipts keep public configuration fingerprints, selector/count reports and added/changed/removed names, not full maps, raw responses, secrets or unknown metadata. Observation opens a fresh read review without automatic network, MCP or write activity. The app version and Room schema 9 stay unchanged.
