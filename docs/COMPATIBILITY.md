# Compatibility and protocol scope

Android 8.0/API 26 minimum; compile/target API 37. Foreground local-only speech needs Android 12/API 31 plus an installed service/model. System recognizer and TTS availability vary by device. Network speech is explicit; physical audio quality is not inferred from text/policy tests.

The app follows the [official Hermes API server reference](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server/) and the upstream gateway/pending-control contracts reviewed during these milestones. No minimum Hermes version string can establish all feature support across changing/forked installs: authenticated capability discovery chooses native sessions/Runs, session streaming or OpenAI-compatible fallback. Unsupported routes remain explicit. Exact unknown-run acknowledgement is exposed only when advertised. Jobs use documented bearer-protected routes after per-connection opt-in; no invented `jobs_admin` capability is assumed.

API-owned sessions support replies and advertised controls. Session inventory/history reads also include Desktop, Discord and other origins in the selected profile; their write controls remain disabled. Shared write ownership is outside scope. Compatibility completion responses do not prove tool/run completion. Native Runs support persisted request keys and sequence-based manual resume; expired receipts/event buffers require server review. Jobs preserve unedited fields. MCP OAuth and dashboard native sign-in use the separate reviewed management bridge. Generic file input, a remote agent backend, automatic approvals and a server-push service are not included. Structured image history and native image picking are available on the development branch; the reviewed share target is implemented.

The shipped Demo is a local simulator. Fixture tests validate request/response and lifecycle behavior without a production agent. The owner's live endpoint/credentials and physical microphone/speaker hardware were not supplied. See the release validation record for device matrix, exact counts and any remaining manual checks.

The Signal Grove `1.1.0-beta.3` preview includes read-only `GET /health/detailed`, `/api/model/options`, `/v1/skills` and `/v1/toolsets`, exposed when their endpoint entries are advertised. Each configured prefix and bearer credential is retained. A successful HTTP diagnostic response may report degraded readiness. The catalog includes unavailable/unauthenticated providers and optional capability/pricing hints; those are server metadata, not a guarantee of runtime availability or cost. Integration execution still happens on Hermes using its configured API-server toolsets.

Schema 5 preserves earlier sessions/receipts while adding a request hash and optional stable channel key. Full requests are bounded to 10 MB outside Room rows; text messages are capped at 64000 UTF-16 code units. The exact header/body is reused on a missing-ID Runs recovery within the existing 23-hour client window. The server's retention/admission guarantees still govern replay. Structured image history, native image picking and request-envelope support are implemented; the reviewed share target is implemented. Requested model overrides are implemented.

Requested `model`, `provider` and `model_options` are now supported on Runs, session chat and compatibility requests when model-option support is advertised. The client emits only the documented reasoning enabled/effort and service-tier option fields. No model/provider SDK or provider credentials are installed on the phone. Choices are requests; session locks, routes and server/provider validation still apply. Advertised per-session locks, forks and active-run steering use exact acknowledgements and durable no-replay operation receipts. Schema 6 adds bounded cached metadata and these receipts. There is no verified clear-lock route. Forking marks the original session branched on Hermes. Steering acceptance is not execution completion. Legacy compatibility chats keep local history and cannot target native session controls without verified native identity.

Android 17/API 37 requires explicit local-network permission for LAN/private-address connections. Settings can request it or open system app permissions; denial does not block public internet endpoints. Permission-aware DNS also detects public-looking names resolving to private addresses. Loopback traffic remains device-local. The operating system enforces permission changes on sockets; a socket blocked after revocation may still surface as a generic network timeout. No permission dialog is launched from startup, a worker, or an uncertain operation replay.

Schema 7 adds tool call/generation/sequence identity, bounded public subagent metadata, response accounting and separate run accounting records. Earlier activity migrates without invented call IDs or usage. Streaming and GET accounting share the durable submission guards. Accounting imports do not guess associations between server message IDs and local response IDs; their run/turn records remain available separately after transcript replacement. Runtime provider/model fields come from runtime metadata, not the top-level requested-model echo. Server token counters can be cumulative; absent counters are never rendered as zero, and no provider cost is calculated from a catalog price. Public child usage/cost fields are displayed when supplied. Live provider fallback and accounting remain unverified.

Schema 8 preserves existing messages/accounting and adds bounded image references. Inline images are normalized into private files rather than SQLite rows; plain JSON strings are never guessed to be media. Server history can contain up to eight image parts per message within the mobile response/memory limits. Native Runs uses an array of user messages whose content contains image parts; session chat uses parts directly, and compatibility history uses per-message content. Frozen requests retain the full exact encoded body independently of display-cache files. A missing/unsupported image in compatibility history cannot be silently removed from the next request. Large pages can retry smaller read-only GETs; mutations retain their no-replay policy. Generic uploaded files, host-file retrieval and arbitrary artifact routes remain unsupported.

Native picking uses existing AndroidX Activity APIs without broad storage/camera permissions or a new provider SDK. Up to three content-URI images can be staged; document fallbacks may allow selecting more, so the app checks the count again. Staging is local, cancellable, scoped and ephemeral. A complete encoded request remains separately frozen for recovery; explicit retry can restore its original JPEG pixels rather than recompressing them. Decoder/source limits and the 10 MB frozen-request limit still apply, especially to compatibility transcript replay. Picker contract dispatch is tested with an intercepted Android result and a test-APK-only provider containing generated pixels. This does not establish physical gallery/cloud-provider/camera behavior or live vision-model support.

The Android share target advertises image MIME types only. It receives transient content-URI access, bounds/validates the selection and caption, and requires an in-app target review before staging. It does not infer a server/session from untrusted intent extras or submit a run automatically. The activity uses a single task instance for warm shares; pending/consumed share state is explicitly restored. Tests launch real Android share intents against the existing activity with generated fixture URIs, including recreation before and after review. Sender-specific URI grants, real galleries and process-death/provider behavior still need physical/live checks.

Named connection profiles are local mobile identities bound to exact API URL/token pairs, distinct from Hermes server profile selection. Credential rotation creates a new scope. Old cached history is available read only after credential removal; uncertain work remains attached to the original credential. The separate native management bridge verifies dashboard identity and requires explicit authenticated server-profile selection. See [management contracts](MANAGEMENT.md).
